# untype-s Functional Requirements

## Functional Requirements
- FR-1: The project MUST build a Swift executable product named `untype`.
- FR-2: `untype --help` MUST exit `0` and document commands, flags, env aliases, and usage examples equivalent to the source project.
- FR-3: `untype --version` MUST exit `0` and print the replacement project's semantic version.
- FR-4: The configuration resolver MUST preserve the source precedence order: CLI flag, current working directory `.env`, `~/.tool-agents/untype/.env`, then shell environment.
- FR-5: Missing required configuration MUST raise typed errors and MUST NOT be replaced by fallback values.
- FR-6: Human transcript output MUST remain separate from diagnostics: transcript/protocol output on stdout, diagnostics/warnings/errors on stderr unless UI mode owns rendering.
- FR-7: The macOS microphone path MUST use native Swift audio capture and emit provider-ready mono PCM at the configured sample rate.
- FR-8: The Soniox provider MUST preserve realtime transcription, partial/final handling, marker filtering, commit/finalization, and typed error mapping.
- FR-9: The ElevenLabs provider MUST preserve realtime transcription, base64 audio chunking, manual/VAD commit, partial/final handling, and typed error mapping.
- FR-10: Rendering MUST support `overwrite`, `append`, and `final-only`, including non-TTY overwrite downgrade and duplicate partial suppression.
- FR-11: The voice-agent protocol MUST preserve marker matching, operator state, section lifecycle, JSONL event schema, and non-secret persisted settings.
- FR-12: LLM refinement MUST preserve Azure OpenAI and Google behavior, fail-open runtime semantics, and accepted stubs for non-implemented providers.
- FR-13: Focused-input delivery MUST not pass processed text through process arguments, persisted settings, or diagnostic logs.
- FR-14: `untype ui` MUST reach native UI parity before the project is declared a final drop-in replacement.
- FR-15: Automated tests MUST cover config, parsers, renderer, protocol, persistence, provider adapter mapping, LLM behavior, and CLI contract behavior.
- FR-16: Manual smoke tests MUST document real microphone, live provider, Accessibility/Input Monitoring, focused input, push-to-talk, overlay, and UI checks.
- FR-17: The native UI MUST let users explicitly copy or save the currently retained transcript timeline and event log, and MUST let users explicitly copy individual raw and processed turn sections, without automatic background persistence.
- FR-18: The native UI MUST expose a current-session conversation history view that shows retained raw dictated user text and recorded refine/translate processed output without persisting the history content across app launches.
- FR-19: The native UI SHOULD evolve toward a modern macOS structure with a native toolbar, leading monitor navigation, collapsible inspector-style settings, dense transcript/history/events work surfaces, and a compact non-activating push-to-talk HUD while preserving all current privacy, configuration, runtime, and export semantics.
- FR-21: Push-to-talk release handling MUST support a configurable `Quick Close` policy that can submit the latest current-turn partial transcript immediately on release, while preserving the existing finalization-wait behavior when disabled.
- FR-22: Push-to-talk release latency logging MUST be opt-in, file-backed, structured, privacy-safe, disabled by default, optionally resettable at application startup, and sufficient to measure elapsed time from release detection to focused-input delivery completion or failure.
- FR-23: Application prompts MUST be loaded from `~/.tool-agents/untype/prompts/` at startup, cover all refinement/translation prompt surfaces plus provider-supported STT prompt/context surfaces, preserve default behavior when unmodified, and avoid logging prompt contents.
- FR-24: When both `refine` and `translate` are enabled for the same submitted section, the application MUST use a configurable composite LLM prompt path that serves refinement and translation through one LLM request while preserving separate single-operator behavior.
- FR-25: Bundled `untype.app` UI sessions MUST deliver focused-input output under the app bundle process identity and restore the captured external foreground target when needed so refined and translated output can be inserted into the intended edit control after users grant permissions to `untype.app`.
- FR-26: Native UI push-to-talk MUST detect configured press-and-hold hotkey press and release while another application has focus when macOS permits global hotkey registration.
- FR-27: Native UI MUST provide an explicit option to manually open the permission/setup popup after startup, independent of automatic onboarding suppression.
- FR-35: The menu-bar icon MUST open a compact dropdown with only the everyday switches (hotkey on/off, push-to-talk vs push-to-listen, protocol mode, the four operators and the translation target), the available hotkeys, and entries with keyboard shortcuts for the Transcript window (⌘1), the History window (⌘2) and Settings (⌘,).
- FR-37: An **Ask** operator (key A, `--ask-default` / `UNTYPE_ASK_DEFAULT`, spoken `ask on/off`) MUST treat the dictated section as a request to the LLM and deliver the model's answer in its place, using an editable, hot-reloaded prompt (`010-ask-system.txt`, `011-ask-user-template.txt`, and `012-ask-translated-user-template.txt` when Translate is also on, so the answer is written in the target language). Refine is skipped while Ask is on; a failed or unconfigured LLM delivers the dictated text unchanged with a warning.
- FR-36: A Settings window MUST present the refinement and translation prompts (and the other prompt files), let the user edit and save them with validation, and hot-reload saved or externally edited prompts so the next push-to-talk turn uses them without restarting untype.

## Non-Functional Requirements
- NFR-1: Swift Package Manager is the authoritative build and test entry point.
- NFR-2: Runtime dependencies must be minimized and vetted before adoption.
- NFR-3: Secrets, transcripts, processed sections, provider endpoints, and protocol payloads must not be persisted where the source project forbids them.
- NFR-4: Work must be decomposed into autonomous phases with durable handoff artifacts.
- NFR-5: No version-control operation may be performed unless explicitly requested.

When enabled, the refine/translate/composite LLM calls stream response tokens for the `azure-openai` provider (Azure OpenAI Chat Completions SSE via `"stream": true`) and the `google` provider (Gemini `:streamGenerateContent?alt=sse`), reading them incrementally via `URLSession.bytes(for:)` behind a new additive `LLMHTTPClient.stream` method while the existing buffered `perform` one-shot path is kept unchanged. The feature is exposed through the four-tier configuration system as the `--llm-streaming` / `--no-llm-streaming` CLI flag pair, the `UNTYPE_LLM_STREAMING` env var, and a native UI settings toggle (emitted through `UntypeUISettings.sessionArguments()`), threaded via a new `streamingEnabled` field on `LLMConfig` and forwarded through both `LLMRefinerFactory` clone sites. Default is off, preserving today's one-shot behavior. When streaming is on but the active provider is neither `azure-openai` nor `google`, the flag is silently inert (no effect, no error) — not a no-fallback-rule violation, since both flag and provider are present and valid. During the overlay `finalizing` phase the displayed text updates progressively as tokens accumulate and settles on the final text; for the composite refine+translate path the overlay shows a best-effort live extraction of `refined_text`/`translated_text` from the in-progress JSON for display only, while the committed `CompositeRefineTranslateResult` is always parsed from the complete response via the existing strict parser. Incremental progress is also emitted to the agent-protocol JSONL output (a new `ProtocolEvent.streamingProgress` case) and the verbose diagnostics stream, with the existing completion-time `sectionProcessed` event unchanged for backward compatibility. Focused-input insertion remains atomic on stream completion (the strictly-parsed final text inserted once, `focused_input.ok=true` preserved), in-flight streams are aborted on new-session teardown via a streaming-task cancellation registry, and all push-to-talk wiring is preserved.
